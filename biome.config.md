## Schema

```json
"$schema": "https://biomejs.dev/schemas/2.4.6/schema.json"
```

Links the config to the official Biome v2.4.6 JSON schema, enabling autocompletion and validation in editors.

## VCS Integration

```json
"vcs": {
    "enabled": true,
    "clientKind": "git",
    "useIgnoreFile": true,
    "defaultBranch": "main"
}
```

| Option | Value | Purpose |
|---|---|---|
| `enabled` | `true` | Enables VCS-aware features |
| `clientKind` | `"git"` | Uses Git as the version control system |
| `useIgnoreFile` | `true` | Respects `.gitignore` — files ignored by Git are also ignored by Biome |
| `defaultBranch` | `"main"` | Used for diffing and changed-file detection |

## Files

```json
"files": {
    "ignoreUnknown": true,
    "includes": [
        "**",
        "!**/node_modules",
        "!**/.next",
        "!**/out",
        "!**/build",
        "!**/dist",
        "!**/coverage",
        "!**/*.min.js",
        "!**/public",
        "!next-env.d.ts",
        "!pnpm-lock.yaml"
    ]
}
```

| Option | Purpose |
|---|---|
| `ignoreUnknown: true` | Silently skip files Biome doesn't know how to handle (e.g., images, fonts) |
| `includes` | `**` includes all files, then `!` prefixed patterns exclude specific paths |

**Excluded paths explained:**

| Pattern | Reason |
|---|---|
| `!**/node_modules` | Third-party dependencies — never lint/format |
| `!**/.next` | Next.js build output — auto-generated |
| `!**/out` | Next.js static export output |
| `!**/build`, `!**/dist` | Generic build output directories |
| `!**/coverage` | Test coverage reports |
| `!**/*.min.js` | Minified files — not human-maintained |
| `!**/public` | Static assets served as-is |
| `!next-env.d.ts` | Auto-generated Next.js type declarations |
| `!pnpm-lock.yaml` | Lock file — auto-generated by pnpm |

## Formatter

```json
"formatter": {
    "enabled": true,
    "indentStyle": "tab",
    "lineWidth": 100,
    "lineEnding": "lf",
    "attributePosition": "auto"
}
```

| Option | Value | Purpose |
|---|---|---|
| `indentStyle` | `"tab"` | Uses tabs for indentation (more accessible, smaller file size) |
| `lineWidth` | `100` | Maximum line length before wrapping. 100 is a good balance between readability and screen usage |
| `lineEnding` | `"lf"` | Unix-style line endings (`\n`). Prevents cross-platform inconsistencies |
| `attributePosition` | `"auto"` | Biome decides whether JSX/HTML attributes go on the same line or wrap to new lines |

## Linter

```json
"linter": {
    "enabled": true,
    "rules": {
        "recommended": true,
        ...
    }
}
```

`"recommended": true` enables Biome's curated set of recommended rules across all categories. Individual rules below either **override** the severity of a recommended rule or **enable** non-recommended rules.

---

### Correctness

Rules that detect code that is guaranteed to be incorrect or useless.

```json
"correctness": {
    "noUnusedVariables": "error",
    "noUnusedImports": "error",
    "useExhaustiveDependencies": "warn",
    "useHookAtTopLevel": "error",
    "useJsxKeyInIterable": "error"
}
```

| Rule | Level | What It Does |
|---|---|---|
| `noUnusedVariables` | error | Flags variables that are declared but never read. Keeps code clean and avoids dead code |
| `noUnusedImports` | error | Flags imports that aren't used. Auto-fixable — Biome removes them on `--fix` |
| `useExhaustiveDependencies` | warn | Warns when React hook dependency arrays are missing values (like ESLint's `react-hooks/exhaustive-deps`). Set to warn because sometimes intentional omissions are valid |
| `useHookAtTopLevel` | error | Prevents calling React hooks inside conditions, loops, or nested functions. Hooks must always be called in the same order |
| `useJsxKeyInIterable` | error | Requires `key` prop on JSX elements inside `.map()`, `for` loops, etc. Missing keys cause rendering bugs |

---

### Suspicious

Rules that detect patterns that are likely bugs or confusing code.

```json
"suspicious": {
    "noDebugger": "error",
    "noConsole": "warn",
    "noDoubleEquals": "error",
    "noExplicitAny": "warn",
    "noArrayIndexKey": "warn",
    "noDuplicateJsxProps": "error"
}
```

| Rule | Level | What It Does |
|---|---|---|
| `noDebugger` | error | Disallows `debugger` statements. These must never reach production |
| `noConsole` | warn | Warns on `console.log`, `console.warn`, etc. Use a proper logger in production. Set to warn to allow during development |
| `noDoubleEquals` | error | Requires `===`/`!==` instead of `==`/`!=`. Loose equality has surprising coercion behavior |
| `noExplicitAny` | warn | Warns when `any` is used as a type. `any` disables type checking — prefer `unknown` or specific types. Warn level because sometimes `any` is pragmatically necessary |
| `noArrayIndexKey` | warn | Warns against using array index as React `key`. Index keys cause issues when list items are reordered, added, or removed |
| `noDuplicateJsxProps` | error | Prevents passing the same prop twice to a JSX element. The second value silently overrides the first |

### Complexity

Rules that suggest simplifications and limit code complexity.

```json
"complexity": {
    "noExcessiveCognitiveComplexity": {
        "level": "warn",
        "options": {
            "maxAllowedComplexity": 20
        }
    },
    "noForEach": "warn",
    "useFlatMap": "error"
}
```

| Rule | Level | What It Does |
|---|---|---|
| `noExcessiveCognitiveComplexity` | warn (max: 20) | Warns when a function's cognitive complexity exceeds 20. High complexity makes code hard to understand and test. Consider breaking it into smaller functions |
| `noForEach` | warn | Suggests `for...of` loops over `.forEach()`. `for...of` supports `break`, `continue`, `await`, and is generally more readable |
| `useFlatMap` | error | Requires `.flatMap()` instead of `.map().flat()`. `flatMap` is a single pass and more expressive |

### Style

Rules that enforce consistent code style and modern JavaScript/TypeScript patterns.

```json
"style": {
    "useConst": "error",
    "useTemplate": "error",
    "useSelfClosingElements": "error",
    "useConsistentArrayType": "error",
    "useImportType": "error",
    "useExportType": "error",
    "useNodejsImportProtocol": "error",
    "useNumberNamespace": "error",
    "useForOf": "error",
    "noNonNullAssertion": "warn",
    "useFilenamingConvention": {
        "level": "error",
        "options": {
            "requireAscii": true,
            "filenameCases": ["camelCase", "PascalCase", "kebab-case"]
        }
    }
}
```

| Rule | Level | What It Does |
|---|---|---|
| `useConst` | error | Requires `const` for variables that are never reassigned. Communicates intent clearly |
| `useTemplate` | error | Requires template literals (`` `Hello ${name}` ``) instead of string concatenation (`"Hello " + name`) |
| `useSelfClosingElements` | error | Requires `<Component />` instead of `<Component></Component>` when there are no children |
| `useConsistentArrayType` | error | Enforces a consistent array type syntax (e.g., `string[]` vs `Array<string>`) |
| `useImportType` | error | Requires `import type { Foo }` for type-only imports. Ensures types are erased at compile time, reducing bundle size |
| `useExportType` | error | Requires `export type { Foo }` for type-only exports. Same benefit as `useImportType` |
| `useNodejsImportProtocol` | error | Requires `node:` prefix for Node.js built-in imports (e.g., `import fs from "node:fs"`). Disambiguates built-ins from npm packages |
| `useNumberNamespace` | error | Requires `Number.parseInt()` instead of global `parseInt()`. More explicit and avoids global scope pollution |
| `useForOf` | error | Requires `for...of` over index-based `for` loops when the index isn't used |
| `noNonNullAssertion` | warn | Warns on non-null assertions (`value!`). These bypass TypeScript's null checks and can hide bugs |
| `useFilenamingConvention` | error | Enforces filenames use `camelCase`, `PascalCase`, or `kebab-case`. Only ASCII characters allowed. Prevents inconsistent naming across the codebase |

### Accessibility (a11y)

Rules that catch accessibility issues in JSX/HTML.

```json
"a11y": {
    "useAltText": "warn",
    "useButtonType": "warn",
    "useAnchorContent": "warn",
    "useValidAnchor": "warn",
    "useKeyWithClickEvents": "warn",
    "noAriaHiddenOnFocusable": "error",
    "useSemanticElements": "warn"
}
```

| Rule | Level | What It Does |
|---|---|---|
| `useAltText` | warn | Requires `alt` attribute on `<img>`, `<area>`, `<input type="image">`, and `<object>`. Screen readers need alt text to describe images |
| `useButtonType` | warn | Requires `type` attribute on `<button>` elements. Without it, buttons default to `type="submit"` which may cause unintended form submissions |
| `useAnchorContent` | warn | Requires `<a>` elements to have accessible content (text, `aria-label`, or child elements). Empty links are invisible to screen readers |
| `useValidAnchor` | warn | Ensures `<a>` elements have valid `href`. Catches `href="#"` or `href="javascript:void(0)"` anti-patterns |
| `useKeyWithClickEvents` | warn | Requires keyboard event handlers alongside `onClick`. Ensures interactive elements work with keyboard navigation |
| `noAriaHiddenOnFocusable` | error | Prevents `aria-hidden="true"` on focusable elements. Focusable elements hidden from the accessibility tree confuse screen reader users |
| `useSemanticElements` | warn | Suggests semantic HTML (`<nav>`, `<main>`, `<header>`) over ARIA roles on generic `<div>` elements |

### Security

Rules that catch potential security vulnerabilities.

```json
"security": {
    "noDangerouslySetInnerHtml": "error"
}
```

| Rule | Level | What It Does |
|---|---|---|
| `noDangerouslySetInnerHtml` | error | Disallows React's `dangerouslySetInnerHTML`. This can lead to XSS attacks if the HTML comes from user input. If you must use it, sanitize the input with a library like DOMPurify and suppress the rule with an inline comment |

---

### Performance

Rules that catch patterns that can hurt runtime or build performance.

```json
"performance": {
    "noBarrelFile": "warn",
    "noReExportAll": "warn"
}
```

| Rule | Level | What It Does |
|---|---|---|
| `noBarrelFile` | warn | Warns on barrel files (`index.ts` that only re-exports). Barrel files increase bundle size because bundlers often can't tree-shake them effectively |
| `noReExportAll` | warn | Warns on `export * from "./module"`. Wildcard re-exports make it impossible for bundlers to determine which exports are actually used |

---

### Nursery

Experimental rules that may change between Biome versions. These are opted in explicitly.

```json
"nursery": {
    "noFloatingPromises": "error"
}
```

| Rule | Level | What It Does |
|---|---|---|
| `noFloatingPromises` | error | Requires all Promises to be handled — either `await`ed, `.then()`ed, `.catch()`ed, or explicitly voided with `void`. Unhandled promises silently swallow errors |

## JavaScript Formatter

```json
"javascript": {
    "formatter": {
        "quoteStyle": "double",
        "jsxQuoteStyle": "double",
        "semicolons": "always",
        "trailingCommas": "all",
        "arrowParentheses": "always",
        "quoteProperties": "asNeeded"
    }
}
```

| Option | Value | Purpose |
|---|---|---|
| `quoteStyle` | `"double"` | Use double quotes for strings: `"hello"` |
| `jsxQuoteStyle` | `"double"` | Use double quotes in JSX attributes: `<div className="foo">` |
| `semicolons` | `"always"` | Always add semicolons. Avoids ASI (Automatic Semicolon Insertion) edge cases |
| `trailingCommas` | `"all"` | Add trailing commas everywhere valid. Makes git diffs cleaner when adding items to lists/objects |
| `arrowParentheses` | `"always"` | Always wrap arrow function parameters: `(x) => x` instead of `x => x`. Consistent and easier to add params later |
| `quoteProperties` | `"asNeeded"` | Only quote object property names when required (e.g., `"kebab-case"` keys) |

## Assist

```json
"assist": {
    "enabled": true,
    "actions": {
        "source": {
            "organizeImports": "on"
        }
    }
}
```

**Organize Imports** automatically sorts and groups imports when you run `biome check --fix` or use the editor action. Replaces the need for `eslint-plugin-import` or `prettier-plugin-organize-imports`.

Import order:
1. Side-effect imports (`import "./styles.css"`)
2. External packages (`import React from "react"`)
3. Internal/relative imports (`import { Button } from "./components"`)

## Overrides

Overrides let you change rules for specific file patterns.

### Test Files

```json
{
    "includes": ["**/*.test.ts", "**/*.test.tsx", "**/*.spec.ts", "**/*.spec.tsx"],
    "linter": {
        "rules": {
            "suspicious": {
                "noConsole": "off",
                "noExplicitAny": "off"
            }
        }
    }
}
```

- **`noConsole: off`** — Tests often use `console.log` for debugging. No need to warn.
- **`noExplicitAny: off`** — Test mocks and fixtures sometimes need `any` for pragmatic reasons.

### Next.js Route Files

```json
{
    "includes": ["app/**/page.tsx", "app/**/layout.tsx", "app/**/loading.tsx", "app/**/error.tsx", "app/**/not-found.tsx"],
    "linter": {
        "rules": {
            "style": {
                "useImportType": "warn"
            }
        }
    }
}
```

- **`useImportType: warn`** — Next.js App Router files sometimes need value imports for components that are both used as types and rendered. Downgraded from error to warn to avoid false positives.

## Severity Levels

| Level | Meaning | Exit Code |
|---|---|---|
| `"error"` | Must fix. Blocks CI (`biome ci` exits non-zero) | 1 |
| `"warn"` | Should fix. Shown in output but doesn't block CI | 0 |
| `"off"` | Rule is disabled entirely | - |

## How to Customize

### Disable a rule for one line

```ts
// biome-ignore lint/suspicious/noConsole: debugging this specific flow
console.log(data);
```

### Disable a rule for a file

Add a comment at the top of the file:

```ts
// biome-ignore-all lint/suspicious/noConsole: this file is a logger
```

### Change a rule globally

Edit `biome.json` and set the rule to the desired severity:

```json
"suspicious": {
    "noConsole": "off"
}
```

### Add a new rule

Find rules in the [Biome rules reference](https://biomejs.dev/linter/rules/) and add them to the appropriate category in `biome.json`.
